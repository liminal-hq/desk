Mode 12h's 16 colours are set through the VGA's colour registers, so the Desk chooses all of them. Eight greys carry every surface, line and text level; eight hues carry the accent, the three halo steps and the icon colours. Compared with 1d, only these change: icon tiles share one dark grey, headings use the body white, the two line greys merge, and the horizon has three bands instead of seven. The halo border, selection, focus and every text colour are the same. The VGA rounds each colour to 6 bits per channel, which nobody will see.

2aHow it fits together
The same split as Lt. Fizz: C owns the hardware, Rust owns everything else, and only integers, pointers and lengths cross between them. The core install is the shell plus Files, Programs and Settings. Every other app is an optional module.

Running a DOS program
1DESK.COM, a few KB of real-mode code, starts DESKCORE.EXE and waits.
2You open FIZZ.EXE. The Desk writes DESK.RUN (program, arguments, folder, window layout), fades the palette out and exits. The DPMI host and all its memory go with it.
3DESK.COM runs the program with the whole machine to itself, so real-mode games like Keen work.
4When it exits, DESK.COM restarts the core with /RESUME. The windows come back and a toast says welcome back (see 1c).
Icons and settings for DOS programs come from the file itself, or from a .PIF-style .DIF beside it: name, icon, memory and sound needs.
Carried over from Lt. Fizz
Only scalars and pointers cross the SDK boundary, with no structs passed by value. Pixel loops use integers. The x87 is only for app maths. Fades and dims go through the DAC, 768 writes instead of a full-frame pass. Redraw only what changed. The VGA write is the slow part on real cards. 8.3 names everywhere, and every build tested in headless DOSBox in CI.
Biggest unknown: DXE3 modules built from Rust go through coff2go32 and DJGPP's dxe3gen. Worth a spike before committing. The fallback is to compile the apps into the core.
